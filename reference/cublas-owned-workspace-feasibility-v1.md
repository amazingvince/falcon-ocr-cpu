A prospective basis construction can avoid guessing equal K chunks. In logical matrices W[768,2304] and X[144,2304], choose distinct K coordinates k_j for columns j=0..143. Set X[j,k_j]=1 and all other X entries to zero; set W[r,k_j]=1+r+1024j and all other W entries to zero. Every output must be exactly `1+r+1024j`, for r=0..767. All codes are distinct positive integers below 2^24, so this has one exactly representable product per dot and no rounding ambiguity. The physical call remains T,N with the original dimensions/strides. Raw float patterns in owned scratch can then be associated with known output coordinates and selected K coordinates, if the hypothesized partial representation actually survives.

An initial fixed selection `k_j=16j` samples the entire K range in one call, without assuming 14 equal partitions. It could establish a candidate output-coordinate layout and sampled K membership, **not every partition boundary**. If further authorized, the 16 predetermined selections `k_j=16j+b`, b=0..15, cover all 2,304 K positions. Requiring the same logged configuration/launches on each call prevents a basis-specific implementation from silently becoming evidence for the original call. Repeating a selection with a different initial scratch pattern distinguishes unwritten bytes. A second independent coordinate-code assignment can test ambiguous matches rather than selecting a convenient interpretation.

Even all-K coverage would verify only the observed routing/layout on those matrices; a minimal two-K membership spot check could test that separately observed contributions coexist as predicted. It would not expose within-partition FMA order, the order in which 14 partials are reduced, or prove that partitions are contiguous. The original real-input scratch would still need to be interpreted using a validated map. In particular, `INPLACE/splitsK=2/workspace=432` for W13 provides no evidence that W13 partial matrices survive in scratch. W2 is the bounded target.
