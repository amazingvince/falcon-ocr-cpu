# BF16 fused observer v5 remains rejected

The independent saved-artifact check confirms the existing rejection. All six archived sources, twenty compiled artifacts, capture and mask files match their recorded hashes; the recomputed lowering audit exactly matches the saved report. Across layers 0, 17 and 19, raw BF16 outputs match completely, while natural LSE differs in 7/9/12 elements and log2 LSE in 7/11/13. Original outputs match the frozen fixture, and requested observation stores are complete. [The metadata receipt](bf16-fused-v5-negative-review-v1.json) preserves these checks and hashes. No GPU work or source edits were performed.

Removing the added probability-sum store did not restore the masked denominator's original MMA reduction. In saved `instrumented-0.ttgir`, line423 converts masked scores from MMA to blocked3. Lines479-487 build the separate blocked3 maximum state. Remaining scalar observation stores consume incoming maximum/denominator, updated maximum, maximum difference, alpha and updated denominator through conversions to blocked2 (lines457-462,496-511,551-552). Probabilities are computed in three layouts: blocked for observation matrices, blocked3 for the denominator, and MMA for the BF16 PV operand. The denominator sum at543-547 and recurrence548 remain blocked3, are carried through the loop at635, and convert back to MMA at643. The full-block denominator remains MMA.

This establishes the remaining observer-use/layout association, not a unique causal store. The candidate still fails both the masked MMA encoding and native local/XOR reduction-shape checks. Its intermediate values cannot be interpreted as native observations, and the unavailable local probability sum cannot be inferred from denominator subtraction. The prospective partial v3 specification does not complete v2.

One defensible next mechanism is a separately authorized stores-only patch of the original emitted PTX, avoiding high-level relowering. It first needs an unchanged-PTX roundtrip through the actual Torch-selected assembler, then arithmetic/control-flow and generated machine-code checks plus all existing full-output and frozen-fixture gates. This is a proposed mechanism, not a validated candidate or a reason to weaken rejection.
